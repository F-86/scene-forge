# 测试规范

## 一、测试策略

> 原型项目以「**快速验证**」为核心目标，测试策略以轻量为原则。

| 测试类型 | 是否引入 | 说明 |
|----------|----------|------|
| 单元测试 | 按需引入 | 仅针对工具函数、数据处理函数 |
| 组件快照 | 不引入 | 原型变化频繁，快照维护成本过高 |
| 视觉验证 | 人工执行 | 对照场景需求文档逐项核查 |
| 场景验收 Checklist | **必须** | 每个场景维护独立验收清单 |

## 二、场景验收 Checklist

每个场景开发完成后，须人工对照以下维度逐项验证，并在需求文档中勾选：

### 数据渲染
- [ ] 空数据时 UI 符合预期（不崩溃、有占位内容）
- [ ] 正常数据时字段显示正确
- [ ] 超长文本不破坏布局

### 状态覆盖
- [ ] Loading 状态有骨架屏 / 加载动画
- [ ] 数据加载完成后状态正确切换
- [ ] 异常状态（如接口报错）有对应提示

### 边界验证
- [ ] 单条数据不出现布局异常
- [ ] 大数据量下页面不卡顿（100 条以上）
- [ ] 字段为空 / null / undefined 时展示占位符而非崩溃

### 场景切换
- [ ] 可通过 Mock 切换器快速切换不同场景
- [ ] 场景切换后页面无残留状态

## 三、单元测试规范

适用范围：工具函数、数据格式化函数、复杂计算逻辑。

```ts
// utils/__tests__/formatDate.test.ts
describe('formatDate', () => {
  it('正常日期应按指定格式输出', () => { ... });
  it('输入为空时应返回占位符「-」', () => { ... });
  it('非法日期不应抛出异常', () => { ... });
});
```

**规则：**
- 测试文件放在源文件同层的 `__tests__/` 目录下
- 测试描述使用中文，说明场景预期而非实现细节
- 每个函数至少覆盖：正常输入、空输入、异常输入三类用例
