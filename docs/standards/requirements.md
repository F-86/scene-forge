# 需求描述规范

## 一、场景需求文档模板

每个场景在 `docs/requirements/scenes/` 下新建独立文件，按以下模板填写：

```markdown
---
场景名称：XXX
创建日期：YYYY-MM-DD
更新日期：YYYY-MM-DD
状态：草稿 / 进行中 / 已完成
标签：#空数据 #边界值
---

## 场景描述
一句话说明这个场景要验证什么。

## 触发条件
- 接口返回数据为空 / 返回 N 条 / 返回异常结构

## Mock 数据规格
| 字段   | 说明   | 取值示例      |
|--------|--------|--------------|
| total  | 总条数 | 0 / 10 / 200 |
| items  | 列表项 | 见 mock.ts   |

## 预期表现
- [ ] 空状态时展示「暂无数据」占位图
- [ ] 超过 100 条时触发虚拟滚动
- [ ] 字段为空时展示「-」占位符

## 不在此场景范围内
- 不验证接口请求本身
- 不验证权限逻辑
```

## 二、场景分类标签

每个场景必须标注以下一个或多个标签，便于后期检索：

| 标签 | 含义 |
|------|------|
| `#空数据` | 列表 / 内容为空 |
| `#少量数据` | 1～5 条 |
| `#正常数据` | 常规数量 |
| `#大数据量` | 100 条以上 |
| `#边界值` | 超长文本、特殊字符等 |
| `#异常状态` | 加载失败、字段缺失 |
| `#加载中` | loading 状态 |

## 三、注意事项

- 每个场景对应一个独立文档文件，禁止多个场景合并在同一文件中
- 场景描述须聚焦于 UI 行为验证，不描述接口实现细节
- Mock 数据规格需与 `mock.ts` 中的字段保持一致
